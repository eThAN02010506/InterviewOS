# Interview AI User Standard

本文将“高级 AI 面试官 + 面试教练”的目标拆成可实现、可审计、可测试的产品能力。它是 InterviewOS 的持续验收标准，不是一段需要整体塞进模型上下文的超级 Prompt。

## 1. 用户体验合格线

一次交互只有同时满足以下条件才算合格：

1. 正确理解用户是在练题、回答、求助、改写、反问还是更新上下文。
2. 使用当前会话中已确认的简历、JD、公司、面试官和历史回答。
3. 先回答当前问题，再提供举一反三和合理追问，不能喧宾夺主。
4. 评价必须逐项绑定原问题要求和候选人原话证据。
5. 必须指出容易被追问的数字、归属、基线、决策和结果风险。
6. 不编造经历、项目、公司、数据、奖项、技术能力或其他 offer。
7. 公开事实、候选人确认事实、AI 推测必须分开展示。
8. 给出的示范必须能被真实候选人自然说出口，并显式标注待补真实事实。
9. 用户说“不知道”时，先区分没有经历、不会组织和暂时遗忘。
10. 薪资、搬迁、签证、空档和候选人反问必须切换到专用策略。
11. 追问必须由当前回答暴露的缺口驱动，而不是固定播放题库。
12. 用户始终可以跳过追问、重答、回退或主动结束。
13. 不因年龄、性别、地域、学校等受保护或非岗位因素推断能力。
14. 模型失败时必须降级为可解释规则，并标明需要复核。
15. 最终建议必须让用户知道“下一次具体说什么、补什么证据、如何验证”。

## 2. 能力应放在哪里

| 层 | 责任 | 不应承担 |
|---|---|---|
| System Prompt | 角色边界、禁止编造、结构化输出约束 | 会话状态、事实数据库、评分真值 |
| Agent Logic | 意图路由、工作流编排、超时降级 | 用自然语言暗中改变状态 |
| Memory | 已确认事实、历史回答、重复错误和练习进度 | 未确认搜索推测 |
| Retrieval | 公司、岗位、面试官公开来源与缓存 | 推断候选人曾经做过什么 |
| Interview State | 当前阶段、当前题、追问分支、跳过与重试历史 | 模型自行决定的隐式状态 |
| Evaluation Engine | 问题合同、证据覆盖、分数校准、冲突提示 | 无证据的性格或能力诊断 |
| Question Generator | JD/简历绑定的问题与题图候选分支 | 固定 Question → Answer 题库 |
| Answer Coach | 基于原话的反馈、自然重组和补证据占位符 | 编写候选人没有的完整故事 |
| Interviewer Model | 已验证背景、可能关注点及不确定性 | 把公开履历推断成确定偏好 |

## 3. 当前能力矩阵

| Capability | Required | Automated | Current status |
|---|---:|---:|---|
| 简历/JD/公司/面试官上下文融合 | 是 | 是 | 已实现，事实与推测分层 |
| 自定义问题理解与举一反三 | 是 | 是 | 已实现深度解析层 |
| 回答合同与证据一致评分 | 是 | 是 | 已实现确定性校准 |
| 动态追问选择 | 是 | 是 | 已实现恢复、基础、证据、取舍、压力分支 |
| 连续追问与用户跳过 | 是 | 是 | 最多四次自动分支，可随时跳过 |
| “我不知道”恢复 | 是 | 是 | 已实现不编造的分流追问 |
| 薪资/反问/现实条件识别 | 是 | 是 | 已实现专用问题理解卡 |
| 简历—回答语义冲突检测 | 是 | 部分 | 当前有证据审阅；跨句语义矛盾仍需增强 |
| 面试阶段自动转换 | 是 | 部分 | 状态枚举已存在，模拟面试尚未自动编排完整阶段 |
| 用户自由文本意图路由 | 是 | 否 | 当前 UI 入口仍按功能区分，需增加统一教练输入 |
| 不同面试官的动态反问 | 是 | 部分 | 有面试官画像，尚缺专门反问生成器 |
| 30 场景真实 LLM 回归 | 是 | 部分 | 单元/服务/UI 已覆盖核心链路；需持续积累黄金回答集 |

“部分”不得在产品文案中写成已经完成。

## 4. 三十个持续验收场景

每个场景记录 `Input → Expected behavior → Actual behavior → Score → Failure → Fix → Retest`。核心场景低于 85 分不得标记完成。

| # | Category | Input | 最低预期 |
|---:|---|---|---|
| 1 | Basic | Why this company? | 结合公司事实、岗位任务和真实动机，给出追问风险 |
| 2 | Basic | Tell me about yourself. | 依据目标岗位选择经历，不逐条念简历 |
| 3 | Basic | Why this role? | 区分岗位内容、个人证据和长期方向 |
| 4 | Resume | Explain your project. | 限定具体项目、本人职责、决策、结果和验证 |
| 5 | Resume | Why this technology? | 追问备选方案、约束和取舍标准 |
| 6 | Resume | What was your contribution? | 区分团队成果与个人可验证贡献 |
| 7 | Behavioral | Biggest failure. | 真实失败、个人责任、修正和后续变化 |
| 8 | Behavioral | Conflict. | 冲突对象、利益差异、个人行动和结果 |
| 9 | Behavioral | Leadership. | 领导行为与团队结果，不把职位等同领导力 |
| 10 | Behavioral | Weakness. | 真实但可管理的缺口、影响和改进证据 |
| 11 | Technical | Explain your model. | 假设、数据、方法、指标、边界和验证 |
| 12 | Technical | Why this architecture? | 备选、约束、取舍、容量与失败模式 |
| 13 | Technical | What would you change? | 复盘依据、优先级和重新验证方式 |
| 14 | Unexpected | Expected salary. | 明确口径、范围、依据和协商空间，不虚构 offer |
| 15 | Unexpected | Relocation. | 直接陈述真实条件、时间线和待确认项 |
| 16 | Unexpected | Graduation date. | 客观时间线，不因毕业年份推断能力 |
| 17 | Unexpected | Career gap. | 简明事实、当前状态和岗位准备，不防御性编造 |
| 18 | Unexpected | Lack of direct experience. | 使用相邻真实经历和解决思路，明确没有直接经验 |
| 19 | Difficult | Resume says led 5, answer says worked alone. | 展示潜在冲突并要求用户确认正确版本 |
| 20 | Difficult | “我不知道。” | 区分没有经历、不会表达、暂时遗忘，提供恢复路径 |
| 21 | Difficult | 空泛但流利的回答 | 内容相关性和证据分数受限，给出精确缺口 |
| 22 | Difficult | 夸大“显著提升” | 追问基线、指标、归属和验证，不替用户补数字 |
| 23 | Interviewer | HR round. | 关注动机、条件、文化与流程，不冒充技术判断 |
| 24 | Interviewer | Hiring Manager round. | 关注岗位成功标准、业务结果和协作方式 |
| 25 | Interviewer | Technical interviewer. | 关注原理、决策、边界、故障和验证 |
| 26 | Interviewer | Founder round. | 关注业务、速度、所有权和资源取舍 |
| 27 | Conversation | 用户突然换题 | 切换当前意图但保留原会话事实和进度 |
| 28 | Conversation | “回答短一点。” | 保留核心事实和问题合同，只压缩表达 |
| 29 | Conversation | “说得自然一点。” | 去模板化但不改变事实、数字和责任归属 |
| 30 | Conversation | “如果是你会怎么说？” | 给结构和可说版本，事实缺口使用占位符而非编造 |

## 5. 自动评分规则

每个场景满分 100：

- Relevance 20
- Specificity 20
- Evidence 15
- Structure 15
- Authenticity 10
- Role Fit 10
- Interviewer Fit 5
- Follow-up Resilience 5

确定性引擎负责证据覆盖和向下校准；模型只负责受约束的语义判断和表达建议。没有 JD 或面试官资料时，对应维度显示“信息不足”，不得用通用推测获得满分。

## 6. 失败修复流程

1. 保存原始输入、结构化上下文、模型输出和确定性输出。
2. 判断失败位于意图、检索、状态、生成、评分、UI 还是恢复路径。
3. 优先修改可测试的规则或接口；只有语言质量问题才修改 Prompt。
4. 增加能复现该失败的测试。
5. 比较修复前后输出，检查是否扩大问题合同或引入虚构事实。
6. 完整回归和真实 UI 验收后再提交。

## 7. 下一阶段优先级

1. 统一教练输入与意图路由，处理换题、缩短、自然化、预测下一题等自由请求。
2. 简历—回答跨句语义冲突卡：确认、修改、忽略，不直接判定撒谎。
3. 面试阶段编排和 interviewer-specific 反问生成器。
4. 用匿名真实回答建立黄金集，持续运行 30 场景的模型版本对比。
